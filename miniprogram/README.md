# meetbuddy 微信小程序端

与 Flutter 用户端共用同一个后端（`server/`，默认 `http://127.0.0.1:8099`），完整覆盖
「密码/验证码登录 → 发现活动流 → 活动详情/报名 → 发布组局 → 群聊（WebSocket 实时）→ 我的」主链路。

## 视觉

与移动端 v2 方向稿同源（参照「圆周旅迹」风格）：天空蓝 `#38B2F2` + 草地绿 `#C4ECA6`
+ 黑胶囊主按钮 `#171A1D` + 大圆角白卡 + 地图化插画（草地形 / 蓝色虚线路线 / 白图钉 / 贴纸）。
设计令牌集中在 `app.wxss` 的 `page` 选择器里，组件只用类名。

## 运行

1. 用微信开发者工具「导入项目」选择本目录（`miniprogram/`）。
2. 详情 → 本地设置 → 勾选 **不校验合法域名**（本地 http/ws 才能通）。
   ⚠️ **模拟器 / 预览 / 真机调试三种模式都依赖这一项**，且它默认可能是关的；
   只要请求是 `http://` + IP，没勾就是"请求发不出去"（不出现在后端日志里）。
   它不进版本库（`project.config.json` 里的 `setting.urlCheck` 才是持久化的那份）。
3. 后端地址在 `config/env.js`，运行时自动区分：模拟器用 `127.0.0.1:8099`，
   真机用 `LAN_IP:8099`。**换 WiFi、或电脑重启后 IP 变了，改 `LAN_IP` 一个常量即可**
   （查法：cmd 执行 `ipconfig`，看「无线局域网适配器 WLAN」的 IPv4 地址）。
4. 正式发布前：换成 https/wss 域名，并在 mp 后台配置 request / socket 合法域名。

## 真机联调

换 AppID 本身不影响连接，但真机（预览 / 真机调试）和模拟器的网络环境完全不同，
下面几件事要一起对上：

- **地址**：手机上的 `127.0.0.1` 是手机自己，必须用电脑的局域网 IP。`env.js` 已自动切换，
  只要 `LAN_IP` 填的是当前电脑 IP 就对了。启动时会打印一行 `[env] apiBase = …`，
  在真机调试的 Console 里能看到实际用的地址。
- **域名校验**：微信不允许 `http` + IP 直连正式环境，只有调试态放行，且**必须手动开**——
  在工具「详情 → 本地设置」勾选 **不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**。
  没勾时三种模式都可能失败，真机上的典型现象是请求**一直 pending、不发包**（DevTools 里
  显示 `Provisional headers are shown`），后端侧**一条连接都看不到**——很容易误判成网络问题。
- **网络**：手机与电脑必须在**同一个局域网**。这条判据由微信自己判断（它看手机当前的
  网络类型 + 目标 IP 是否同网段），所以**拓扑比"能不能 ping 通"更关键**：
  - 稳的：手机和电脑连**同一个路由器 WiFi**；或**电脑开热点、手机连电脑**。
  - 不稳的：「**手机开热点、电脑连热点**」。此时手机自身的上网网络类型是蜂窝流量，
    微信常判定为"不在局域网"，于是 **IP 型 URL 的请求被直接拦下**（ICMP 仍能 ping 通，
    极具迷惑性——ping 通不代表请求发得出去）。
  - 路由器/热点的「AP 隔离 / 客户端隔离」会让两端互相 ping 不通；手机上的 VPN / 加速器要关掉。
  - 开发者工具「设置 → 代理设置」选**不使用任何代理**，否则真机请求可能被带偏。
- **防火墙**：Windows 需放行后端进程的入站。本机已存在一条放行
  `…\Eclipse Adoptium\jdk-21.0.8.9-hotspot\bin\java.exe` 的入站规则（就是跑 8099 的那个进程），
  换 JDK 或换机器后要重新放行。
- **自检**：手机浏览器打开 `http://<LAN_IP>:8099/api/auth/login/password`——
  能看到 JSON（哪怕报方法不允许/未登录）就说明网络层通了；一直转圈或"无法访问"则是
  网段 / AP 隔离 / 防火墙的问题，与小程序代码无关。

**先分流，再对症**：在电脑上 `netstat -ano | findstr 8099`（或
`Get-NetTCPConnection -LocalPort 8099`）。**只有 `LISTENING`、没有任何连接** ⇒ 请求根本没
离开手机，往域名校验 / 局域网判定查；**有连接但没响应** ⇒ 才往后端、防火墙、网段查。

真机连不上时的对照：

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示「连不上后端 http://127.0.0.1:8099」 | 真机跑的还是回环地址 | 确认 `env.js` 的 `LAN_IP` 是电脑当前 IP |
| 请求一直 pending、**后端侧零连接** | 请求没离开手机：没勾「不校验合法域名」，或微信判定手机不在局域网（**手机开热点**的典型症状） | 勾上「不校验合法域名」；拓扑换成"共用路由器 WiFi"或"电脑开热点、手机连" |
| 有连接但一直没响应 / 提示「连不上后端 http://172.x.x.x:8099」 | 手机与电脑不同网段 / AP 隔离 / 防火墙拦了入站 | 换同一 WiFi、关手机 VPN、放行后端进程入站 |
| 群聊发消息提示「连接已断开…」 | WebSocket 没连上（与 http 同一个地址） | 同上，先让 http 通 |

## 结构

```
config/env.js          后端地址（唯一需要改的地方）
utils/api.js           统一请求层：拼 URL、注入 Bearer、拆 {code,message,data} 信封
utils/socket.js        WebSocket 通道：ws://…/ws?token=，30s 心跳，chat/ack/offline/error 帧分发
utils/format.js        时间徽标 / 相对时间 / 距离等展示口径（与 Flutter 端一致）
components/map-scene/  地图插画组件（纯 CSS + base64 SVG 虚线路线）
custom-tab-bar/        自定义黑胶囊底部导航（发现 / 消息 / 我的）
pages/login            登录（密码 / 验证码 / 注册）
pages/feed             发现：分类 chips + 活动卡（地图封面 + 名额进度）
pages/detail           详情：信息卡 + 报名/取消 + 群聊入口（悬浮报名条）
pages/create           发布：分卡表单 + 标签选择（地标下拉决定经纬度）
pages/chat-list        消息列表（未读徽标喂给自定义 tab bar）
pages/chat-room        群聊：乐观发送 + ack 确认 + 只读降级（错误码 3104）
pages/profile          我的：数据卡 + 我发起的 / 我报名的
```

## 与 Flutter 端的已知差异

- 登录没有「微信一键登录」按钮：后端还没有微信 code 换登录态的接口，放一个假按钮是骗人，等后端支持后再加。
- 发布页的时间选择用一次可编辑弹窗（格式 `10月17日 14:00`，留空用默认值），
  替代小程序原生"日期 + 时间"两次弹窗，减少打断；解析失败自动回落默认时间。
- 发布页的人数/信用分用步进器（小程序 slider 在真机上的触达体验一般）。
- 就近筛选固定演示坐标（北京国贸），与 Flutter 端一致。

## 约定

- 页面永远不碰 `code`：`utils/api.js` 里非 0 一律 reject `{code, message}`，页面只管提示。
- tab 页 `onShow` 里先做登录守卫（未登录 `reLaunch` 到登录页），再 `setSelected(n)` 同步底部导航。
- WS 连接生命周期只在 `app.js` 管理，页面只订阅事件。
