# 09 - 兴趣标签引导

> 2026-10-15 TE 拍板开发。附带拍板：聊天发图片功能**砍掉**（见末尾）。

## 一、为什么做

匹配评分公式（见 `01-技术决策与业务规则.md` 第七节）里「标签重合」占 **0.3 权重**，
是四项里最高的一项，但此前用户**没有任何入口**设置自己的兴趣标签——`user_tag` 表、`PUT /api/user/tags`
端点在早期就铺好了，前端却从没接。结果是匹配只剩距离维度在起作用，标签重合恒为 0，
"找到合拍搭子"的产品承诺落空。本功能把这条链路在用户侧补完。

## 二、后端改动（本次）

- `UserVO` 增加 `tags: List<String>`；`getCurrentProfile()` 与 `updateProfile()` 返回值都回填标签
  （按 `user_tag` 主键升序，即插入顺序）。
- `UserProfileVO` 增加 `tags`；`getProfile()` 回填对方标签，公开展示。
- 标签的**写入端点 `PUT /api/user/tags` 早已存在**，本次未改：
  - 覆盖式更新（传什么就是什么，能表达"删掉某个标签"）；
  - 后端 `MAX_TAGS = 20`，超出的忽略；空串/纯空白/重复自动跳过；每项 `trim()`；
  - 单条写入校验只认 `/uploads/`、`/images/` 路径段（与头像同口径），外链一律拒。

为什么要回填到 `UserVO` 而不是另开一个 `/api/user/tags/get`：标签与资料同属"我是谁"，
`/me` 一次带全最省请求；`updateTags` 仍走独立端点，是因为它是覆盖式写、和资料写语义不同，
放一个 PUT 里反而难表达"只改标签不动昵称"。

## 三、前端改动

### 1. 「我的」页（profile）
- 有标签：在统计卡下方展示一排水墨灰 chip（`.tag.plain`）。
- 无标签：替换成一张轻引导卡（🏷️ + 文案 + 「＋ 添加」），整卡可点进编辑，**不打断浏览、不弹窗**。
- 编辑资料面板新增「兴趣标签」段：
  - 已选标签：彩色 pill，点一下即删（✕ 角标提示可移除）；
  - 建议池：26 个预设（剧本杀/桌游/飞盘/健身/探店/露营/摄影……），点选切换高亮；
  - 自定义：输入框 + 「添加」按钮（回车也可），限 10 字、去重、封顶 20；
  - 底部 `n/20` 计数。
- 保存时：`PUT /api/user/profile` + `PUT /api/user/tags` 两个请求一起发；标签写失败则回滚
  `saving` 并提示，不破坏已存的资料。全局缓存 `globalData.me.tags` 同步刷新，避免 `onShow` 被旧缓存覆盖。

### 2. 他人主页（user-profile）
- 简介卡下方新增「兴趣标签」段，展示对方 `tags`（无则整段隐去）。
- 价值不只是展示：别人主页都有标签，反向引导"我也该加"，形成从众式引导。

### 3. 预设标签的规范性
`docs/02` 定的规则：兴趣是开放集合，做成字典表每加一个就要改数据，收益为零；
规范性由前端的建议池负责，不靠数据库约束。预设列表写在 `profile.js` 的 `TAG_SUGGESTIONS`，
改一处即可，不影响后端。

## 四、校验口径（前后端一致）

| 项 | 规则 |
|---|---|
| 上限 | 20 个，超出忽略 |
| 单条长度 | ≤ 10 字（前端拦截 + 后端 trim） |
| 空白/重复 | 自动跳过/忽略 |
| 排序 | 按插入顺序；`/me`、他人主页同源 |

## 五、砍掉：聊天发图片

TE 2026-10-15 明确：**聊天发图片不做**。理由：
- 聊天的定位是"约起来"的轻量协调通道，文字 + 活动/搭子卡片已够用，在聊天内传图是过度功能；
- 图片已有正经承载处（活动封面、用户头像），不必在聊天里再开一条图片链路；
- 省掉图片上传、消息体类型扩展、iOS `<image>` 加载 http 图等一连串复杂度。

此前它仅为候选想法、从未进代码，故本次无代码可删，仅在此留档。
