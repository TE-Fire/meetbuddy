# 08 - 用户头像

> 用户原话（2026-10-15）：「接下来该做什么，给用户加一个头像如何」→ 拍板走**上传图片**方案。
> 本文定稿头像的规则与口径。任何改动 `pages/poster`、`pages/profile`、各头像展示点者，先读本文件。

## 一、目标

给每个用户一张真实头像，替换全站当前的首字母占位块。直接利好已上线的「他人主页」与「勋章墙」——
此前这两处都是字母块，有头像后社交纵深立刻成立。

## 二、来源（已拍板：仅上传图片）

| 来源 | 结论 |
| --- | --- |
| 上传图片 | **采用。** 复用 `POST /api/upload/image`，用户在个人页选图后回写 `user.avatar` |
| 微信头像授权 | 不做。新接口只返临时 path、链接会过期需转存，且连带触发昵称同步改造，复杂度被低估 |
| 系统预设头像 | 不做。但作为「无图时的默认态」保留（即首字母 + 配色） |

**回退策略（全局统一）**：`avatar` 为空时，展示首字母 + 配色（现状逻辑），不破坏任何页面。

## 三、存储与校验

- 字段：实体 `user.avatar`（已存在），存**后端相对路径** `/uploads/xxx.jpg`；`UserVO` 已序列化该字段。
- 写入入口：`PUT /api/user/profile`（`ProfileUpdateRequest` 新增 `avatar` 入参，可空，传 `null` 表示不改）。
- 校验（`UserService.updateProfile` 内）：
  - 非 `null` 时 `trim()` 后非空、长度 ≤ 255；
  - **归一化后按 path 段校验**：上传接口按请求 Host 返回绝对地址（如 `http://127.0.0.1:8099/uploads/x.jpg`），
    先截掉协议 + host 取 path，再要求 path 以 `/uploads/` 或 `/images/` 开头，其余一律拒（`PARAM_ERROR`）。
    落库统一存相对路径，所有设备刷新时由前端 `imgUrl` 拼自己的 apiBase 自愈。
    原因：头像直接进 `<view>` 的 `background-image`，若写进任意外链等于开放存储型 XSS / 钓鱼图入口，必须锁死来源；
    只放行本服务上传目录，外链（如 `http://evil.com/a.png`）在归一化后 path 为 `/a.png`，前缀不符即拒。
- 不引入裁剪：V1 原图上传，圆形展示靠 CSS `border-radius: 50%`；后续要方图裁剪再单独加 canvas 裁切。

## 四、透传（已就绪，无需改动）

所有用户相关 VO 在 M8 阶段已带 `avatar` 并赋值，展示侧直接取用即可：

| 接口 / 用途 | 字段名 |
| --- | --- |
| `GET /api/user/me`、`PUT /api/user/profile` | `avatar` |
| `GET /api/user/{id}/profile`（他人主页） | `avatar` |
| `GET /api/chat/sessions`（私聊） | `peerAvatar` |
| 活动详情 组织者 | `organizerAvatar` |

`UserProfileServiceImpl` / `ChatServiceImpl` / `ActivityServiceImpl` / `BuddyServiceImpl` 均已 `setAvatar`。

## 五、前端展示口径

1. **圆形容器**：头像统一 `.avatar` 类，`border-radius: 50%`（或原 profile 的 60rpx 圆角，维持现状）、`overflow: hidden`、固定尺寸。
2. **真图走 `background-image`，禁用 `<image>` 组件**：
   iOS 微信 8.0.58+ 的 `<image>` 不加载 http 图片（WebView 混合内容限制），已踩过三次。
   真图地址必须用 `style="background-image: url('{{x.avatarUrl}}')"` 渲染，且 `x.avatarUrl` 由
   `utils/format.js` 的 `imgUrl()` 归一化（同 feed / 详情封面图）。
3. **首字母回退**：`avatar` 为空时，容器显示首字母（`nickname[0]`）+ 现有着色，真图层不显示文字。
4. **预处理位置**：每个页面 js 组装数据时加 `avatarUrl: fmt.imgUrl(x.avatar)`（或对应字段名），
   WXML 只读 `avatarUrl`。复用 `user-profile.js:32` 现成写法，不引入 WXS（WXS 读不到动态 `env.apiBase`）。

## 七、验收标准

- 个人页选图 → 上传 → 保存 → 刷新后显示真图；圆形裁切正常。
- 任意 7 处展示点：有头像显示真图、无头像回退首字母，两种状态都正确。
- 他人主页查看对方头像正常（隐私字段仍不含手机号）。
- 脏数据：`PUT /api/user/profile` 传 `avatar: "http://evil.com/a.png"` 或绝对外链，返回 `PARAM_ERROR`，库不变。
- 未登录 / 无头像用户旧数据不受影响（首字母照常）。

## 八、明确不做 & 升级路径

- 不做微信头像授权（见第二节）。
- 不做系统预设头像库（回退态已满足）。
- 不做头像裁剪（V1）。
- 后续若要微信头像：需正式 AppID + AppSecret + 已发布版本，且把临时 path 下载转存到 `/uploads/` 再写 `avatar`——届时只改「来源选择」与「转存」两处，展示层不动。
