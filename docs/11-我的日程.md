# 11. 我的日程（时间轴视图）

> TE 2026-10-15 拍板：在活动列表排序之后，继续做"我的日程/时间轴"。

## 背景

「我的」页原本把"我发起的""我报名的"拆成两个独立区块，但用户真正想看的是**"我这周/今天有哪些局"**——按时间聚合的全局视图。本变更新增独立 `pages/schedule` 页，把两类活动合并后按日期分组展示成时间轴。

## 设计口径

- **后端零改动**：复用已有的两个端点 `/api/activity/mine/organized` 与 `/api/activity/mine/joined`，前端并发拉取（各 `size=100` 一次拉全）、按 `id` 去重合并。发起者不会出现在自己的报名列表里，但去重仍兜底，避免理论上的重复渲染。
- **身份标注**：合并时给每条打 `role`（`host`=我发起 / `join`=我报名），卡片上用小标签区分。
- **日期分组**：按 `startTime` 的本地日期（`yyyy-mm-dd`）分组，组标题走 `今天 / 明天 / 后天 / 周X / M月D日`；未来日期（含今天）在上、按时间升序，过去日期在下、最近的过去排前。组内按 `startTime` 升序。
- **过去判定**：以 `endTime` 是否早于当前时间为准——`ONGOING`（进行中）不算过去，不灰显；只有真正 `FINISHED`/`CANCELLED` 且已过的才灰显并标「已结束」。
- **顶部筛选**：全部 / 我发起 / 我报名，纯前端过滤。
- **入口**：`profile` 菜单新增「我的日程」一行，点击 `navigateTo` 进 `schedule` 页（与「我发起的局/我参加的局」的页内滚动 `jumpTo` 不同，这是独立子页）。

## 前端改动

- 新页面 `pages/schedule/{js,wxml,wxss,json}`：并发拉双列表 → 合并去重 → 按日期分组时间轴 → 顶部 segment 筛选；支持下拉刷新。
- 复用 `format.js` 的 `fmtHm`/`shortAddr`/`statusLabel`，日期分组/标签逻辑写在页内（与 `feed`/`profile` 各自持有一份 `CATEGORY_ICONS` 的风格一致）。
- `app.json` 注册 `pages/schedule/schedule`；`profile.wxml` 菜单加入口；`profile.js` 加 `openSchedule`。

## 联调结论

- 两个 mine 端点均返回含 `startTime`/`endTime`/`status`/`category`/`address`/`currentParticipants`/`maxParticipants` 的 `ActivityVO`，前端聚合所需字段齐全。
- 前端为纯聚合/分组逻辑，无新后端依赖；本机无法跑模拟器渲染，需用户在开发者工具清缓存重编译查看。

## 边界与未做

- 日程数据来自两个分页接口各取 `size=100`，对单人活动量级足够；若未来单用户活动超百，需后端加聚合端点（届时按 `startTime` 排序、跨页合并）。
- 未做日历月视图（格子日历）——时间轴更贴合"马上要去的局"这个核心诉求，且实现更轻。
- 同批候选的活动编辑/改期、关注关系仍未做，待 TE 另拍板。
