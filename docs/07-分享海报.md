# 分享海报

> 本文定"活动分享海报"的生成规则，是代码实现的唯一依据。
> 2026-10-15 TE 拍板开发；范围仅限"生成海报 + 存相册"，不含微信原生转发（`onShareAppMessage`）。

## 一、要解决什么

项目此前没有任何对外传播入口：活动详情只能在站内看到，老用户想拉朋友进来，唯一办法是让对方自己搜小程序。海报补的就是这一步——把一场活动的关键信息压成一张图，用户存到相册后能发朋友圈、发微信群，图上带着"去哪儿找小程序"的引导。

承载物之所以是**图片**而不是原生转发卡片，是因为朋友圈不支持小程序转发卡片，而图可以；代价是分享动作多一步（存相册 → 手动发），换来的是覆盖面。

## 二、为什么不在图里画小程序码

微信生成小程序码（`wxacode.getUnlimited`）需要**正式 AppID + AppSecret + 已发布版本**，三者本项目当前都没有：后端 `application.yml` 里只有 JWT 密钥，没有任何微信凭据；本地后端还是 `http://IP:8099`，小程序码的 `scene` 落地页也只能指向线上版本。硬画一个"像二维码的方块"是骗人——用户真去扫会扫不出来，比没有更糟。

所以本地/开发阶段**不画码，画引导块**：右下角一枚黑底圆角块，写"微信小程序 / 搜「搭子」"。它是纯文字引导，不暗示可扫。接入正式凭据后的升级路径见第五节。

## 三、海报内容与分区

画布按 **750 × 1240** 的设计坐标绘制（宽高比 1:1.65），导出时按 `dpr` 放大，因此在任何机型上清晰度一致。分区自上而下：

| 区域 | 内容 | 说明 |
|---|---|---|
| 封面 | 活动封面图，`aspectFill` 居中裁切，高 520 | 无封面或图片加载失败时降级为品牌渐变底 + 分类图标 |
| 状态角标 | 黑底胶囊，压在封面左上角 | 取 `statusText`（报名中 / 已满 / 已结束…） |
| 标题 | 活动标题，粗体 54px，最多 2 行 | 超长按两行截断并以省略号收尾 |
| 标签行 | 分类 chip + 名额 chip（`信用分 ≥ n` 有才显示） | 与详情页同一套文案口径 |
| 信息三行 | 时间 / 地点 / 名额 | 标签（蓝）+ 值（深灰），值超宽截断 |
| 组织者行 | 首字头像圆 + 昵称 + "发起" | 头像圆用与 App 一致的蓝色渐变 |
| 底部品牌区 | 左："搭子" + 标语；右：引导块 | 引导块为 `docs` 第二节所述的降级方案 |

文案口径**复用 `utils/format.js`**，不另起一套：时间用 `fmtTime`（`10月17日 19:30`），地址用 `shortAddr` 截断，状态用 `statusLabel`。海报与页面上显示的必须是同一个字符串，否则同一场活动会出现两种说法。

## 四、生成与保存的实现要点

绘制走 **canvas 2d**（`type="2d"`），不用已废弃的旧接口。三条约束值得记下来，都是踩过或必然踩的：

- **设计坐标与设备无关**。绘制坐标固定在 750 × 1240 的设计栅格上，canvas 位图 = 750 × 1240 × dpr，`ctx.scale(dpr, dpr)` 后所有绘制坐标直接用设计值，不做任何换算。**不要用 rpx**：rpx 会让设计坐标随屏幕宽度漂移，换行点和裁切位置跟着变。
- **预览只能缩 CSS 盒子，不能缩位图**。750px 宽在手机上超过屏幕，做法是把 canvas 的 **CSS 盒子**设成预览尺寸（左右各留 32px，并给标题/提示/按钮留约 260px，两者取小保证一屏放得下），由 canvas 自己把位图缩进盒子；位图尺寸不动，导出仍是原始分辨率。⚠ **不能用 CSS `transform: scale()` 缩**：canvas 2d 在 iOS 上是同层渲染的原生层，`transform` 会被忽略，画布按 1:1 铺满屏幕并溢出父容器（父级 `overflow: hidden` 也拦不住）——实测表现是海报大到只能看见左上角一块。缩放比例由 `windowWidth` / `windowHeight` 现算，不写死。
- **取景区省略，输出尺寸显式给**。`wx.canvasToTempFilePath` 的 `x/y/width/height` 全部省略，取景整幅画布——不去指定区域，是因为 `width/height` 的单位（CSS px 还是位图像素）在 2d canvas 上跨平台解释不一致，容易只导出左上角一块。但 `destWidth/destHeight` **必须显式给**：它的默认值是「`width` × 屏幕像素密度」，而 `width` 默认取 canvas 的**显示**宽度；预览盒为了塞进屏幕已经缩过，照默认走会导出一张小得多的图。这里按位图尺寸给（750 × 1240 × dpr），并把长边压到 4096 以内——微信对临时图片文件有尺寸上限，dpr=4 的机型会超。
- **封面图异步，先画后补**。绘制分两趟：先按"无封面"渲染一遍整张海报（此时已可保存），图片 `onload` 后再整张重绘一次。这样网络图挂掉时海报依然完整，不会留一块空白等着。

保存走 `wx.saveImageToPhotosAlbum`。三种失败要区分对待：用户拒绝授权 → 弹窗引导去"设置 → 允许保存到相册"；用户主动取消 → 不提示（打扰）；其他 → 提示重试。

## 五、接入正式小程序码的升级路径

拿到正式 AppID + AppSecret 且小程序有已发布版本后，按下表切换即可，前端其余部分不动：

| 步骤 | 动作 |
|---|---|
| 1 | 后端配 `meetbuddy.wx.app-id` / `app-secret`，实现取 `access_token`（缓存 7000s） |
| 2 | 新增接口取小程序码：`wxacode.getUnlimited`，`scene=activity_<id>`（≤32 字符），`page=pages/detail/detail` |
| 3 | 码图回传后落 `/uploads/`，接口返回相对路径，前端用现成的 `fmt.imgUrl()` 归一化 |
| 4 | 海报页把底部引导块换成码图；`img` 的 `onerror` 仍回落到引导块，避免接口挂了海报不可用 |

在第 1 步之前，海报页**不请求任何码接口**——省一次必然失败的请求，也避免留下一段永远不会走通的死代码。

## 六、入口与验收标准

入口放**活动详情页底部操作条**最左，一枚紧凑按钮：**三点连线的分享图标 + 「分享」二字**，与"进入群聊""报名参加"并排。放这里是因为分享的时机就是"我看完这个活动觉得不错"——详情页是唯一有这个语境的页面；菜单或独立 tab 都够不着这个时机。

图标用 CSS 画（`currentColor` 上色，跟随按钮文字色），不用 emoji：emoji 在不同机型渲染大小不一，且原来的 🖼️ 会被读成"看图"而不是"分享"。

验收标准：

1. 详情页底部条能看到海报按钮，点击进入海报页且带 `id`；
2. 海报页 3 秒内出图，封面、标题、状态、时间、地点、名额、组织者、底部品牌区齐全；
3. 活动无封面（或封面是坏地址）时，封面区显示渐变底而非空白/破图；
4. 标题超过两行时按两行截断且带省略号，不溢出画布；
5. 点"保存到相册"能在相册看到 PNG；拒绝授权时给出可操作的引导，用户取消时不弹提示；
6. 海报为纯前端渲染，不新增接口、不改动后端。

## 七、明确不做

- **微信原生转发（`onShareAppMessage`）**：与海报是两条独立的分享路径，本次不做，需要时另开。
- **海报模板/皮肤选择**：一套版式够用，多套要配管理端。
- **带用户个人二维码/头像的海报**：涉及个人信息展示口径，未定稿不做。
