# 活动编辑 / 改期（M 扩展）

组织者发起活动后，经常需要改时间、换地点、调人数上限。本期补齐"自助编辑"闭环：
详情页给组织者一个「编辑」入口，进独立编辑页回填原信息，`PUT` 回后端落库。

## 一、范围与口径

- **可编辑字段**：标题、分类、时间（开始/结束）、地点（地标+详细地址）、人数上限、信用分门槛、标签、介绍、配图。
- **可编辑状态**：`OPEN`（报名中）与 `FULL`（已满员）均可改；`ONGOING` / `FINISHED` / `CANCELLED` 拒绝编辑。
  原来的实现只允许 `OPEN`，满员后就无法改期，与"改期"诉求相悖；本期放宽到 `OPEN/FULL`，与最初推荐口径"**started 后才禁改**"一致（即未开始都能改，已开始/结束不再允许）。
- **人数下限保护**：编辑页把人数下限抬到「当前已报名数」（`maxParticipants` 的 stepper `data-min` 绑定 `minParticipants`），避免把上限调小于已报名人数、把已报名的人"挤掉"。后端仍有双重校验：`maxParticipants < currentParticipants` 直接拒绝。
- **地点变更同步**：编辑会重写 `lng/lat/address` 并 `geoStore.upsert`，就近筛选按新坐标圈人，不残留旧位置。
- **标签 / 配图**：编辑时整表替换——先 `DELETE` 旧 `activity_tag` / `activity_image`，再按新列表 `INSERT`，前端改删标签/图片即时生效。
- **状态不变**：编辑不改变 `status`，OPEN 仍是 OPEN、FULL 仍是 FULL（只有人数真的降到低于已报名才会自然不再 FULL，但下限已挡住）。

## 二、权限与校验（后端 `ActivityServiceImpl.update`）

| 校验 | 行为 |
| --- | --- |
| 活动存在 | 不存在 → `NOT_FOUND` |
| 操作者 = 组织者 | 否 → `FORBIDDEN`「只有组织者可以操作该活动」 |
| 状态 ∈ {OPEN, FULL} | 否 → `PARAM_ERROR`「活动已开始或已结束，无法编辑」 |
| 结束晚于开始 | 否 → `PARAM_ERROR` |
| 上限 ≥ 已报名 | 否 → `PARAM_ERROR`「人数上限不能小于当前已报名人数 N」 |

入口 `ActivityController`：`PUT /api/activity/{id}`，复用 `ActivityCreateRequest` 作为请求体（全量更新，不部分打补丁——部分更新会让"编辑后字段丢失"的责任难以界定）。

## 三、前端改动

- 新增 `pages/activity-edit/*`（4 文件），结构复用发布页 `pages/create` 的表单与时间滑动面板，区别：
  - `onLoad` 拉 `GET /api/activity/{id}` 回填所有字段；
  - 人数 stepper 下限绑定 `minParticipants`（= 已报名数，至少 1）；
  - **真实日历日期保护**：编辑的活动开始日可能超出发布页"今天~大后天"的 4 天窗口，若直接走面板日期链会截断日期。编辑页把真实日期存进 `_baseDate`，`confirmTime` / `_computeRs` 在编辑模式下用 `_baseDate` 拼时间，时间面板只调"时刻"，不改日历日（日期 chips 仅作展示，保存以 `_baseDate` 为准）；
  - 提交走 `api.put`，成功后 `navigateBack`（详情页 `onShow` 自动重载）。
- `pages/detail`：`decorate` 加 `canEdit = organizer && (status OPEN|FULL)`；组织者卡下方加「✏️ 编辑活动」入口，跳 `activity-edit?id=`；`app.json` 注册页面。

## 四、未做（out of scope）

- **改期通知**：编辑保存后**不主动推送**给已报名者（本期只改库，由用户自行在群里同步）。若要"改时间自动 @all 提醒"，需接入 `NotificationService`，留待下一期。
- **ONGOING 紧急改地点**：进行中活动不允许编辑，需组织者取消后重发。
- **历史版本 / 撤回**：编辑即覆盖，无草稿、无历史。

## 五、联调结论

- `OPEN` 活动 `PUT` 全量字段 → `code:0`，`GET` 回显新值；
- `FULL` 活动 `PUT` → `code:0`（放宽生效）；
- `maxParticipants` 小于已报名数 → `PARAM_ERROR`；
- `ONGOING` 活动 `PUT` → `PARAM_ERROR`「活动已开始或已结束，无法编辑」；
- 非组织者 `PUT` → `FORBIDDEN`。
